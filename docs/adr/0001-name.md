# 0001 — Name: Janus (雅努斯)

- Status: accepted
- Date: 2026-11-24
- Decision owner: HugoXK
- Supersedes: the first draft of this ADR

## Context

Janus is a personal market agent with two jobs:

1. **Memory** — record what the user believed, what they knew, and how it turned
   out.
2. **Foresight** — turn that record into calibrated probabilities, scenarios,
   and regime changes.

The name has to work as a GitHub repository, a PyPI package, a CLI, a DSH
plugin, a paper, and a brand. It must not promise returns, must not sound like a
trading bot, and must not collapse into one half of the loop.

## Decision drivers

1. **Dual nature.** Memory and foresight must live in one image.
2. **Concrete, not abstract.** A real word or figure, not a made-up compound.
3. **Short.** One or two syllables; easy to say, type, and remember.
4. **No false friends.** No negative connotation in English or Chinese.
5. **Domain fit.** Gates, transitions, thresholds, regime changes.
6. **Bilingual.** A Chinese name that is not a transliteration-only afterthought.
7. **Room to grow.** Works for a CLI, a plugin, a paper, and a brand.
8. **Low collision risk** in agent and market tooling.

## Candidates

| Name | Meaning | Strength | Risk |
| --- | --- | --- | --- |
| **Janus** | Roman god of gates, transitions, beginnings, endings; two faces | Exactly memory + foresight; January; instrument not oracle | “Two-faced” false friend; collisions with Janus Henderson, Janus Gateway, JanusGraph |
| Touchstone | A stone used to test gold | Calibration and verification; concrete; finance-adjacent | Only one half (testing), no foresight; not bilingual |
| Hindcast | Testing a forecast model on historical data | Calibration and backtesting | Technical meteorological meaning; no memory; hard to say |
| Vintage | A point-in-time version of data | Point-in-time; elegant | Abstract and data-nerdy; not a product |
| AsOf | The core query | Precise; developer tool | Too abstract for a product; awkward as a name |
| Sextant | Navigation instrument | Position and direction; concrete | No memory or calibration; collisions |
| Orrery | Mechanical model of the solar system | Past and future motion; concrete | Obscure; hard to spell; no memory |
| Almanac | Book of records and forecasts | Records plus forecasts | Old-fashioned; collisions; no dual image |
| Folio | Page or portfolio | Finance plus record | No foresight; collisions |
| Debrief | Review after an event | Memory and learning | Only one half; no foresight |
| OpenFinch / Jay / Jackdaw / Magpie | Birds that cache or collect | Concrete; bird theme | Cute; collection is not calibration; collisions |
| Roost | Where birds settle | Calm; hosting metaphor | Rest and passivity; no foresight |

## Decision

Use **Janus** (雅努斯).

- Primary tagline: **Look back to reason forward.**
- Secondary tagline: **Past in memory. Future in probabilities.**
- Chinese tagline: **回望以推理，记忆以预测。**
- Repository: `HugoXK/janus`.
- Package: `janus-market` on PyPI/npm.
- CLI: `janus`.
- DSH plugin: `@hugoxk/janus-dsh`.

## Why Janus

Janus is the Roman god of **gates, doorways, transitions, beginnings, and
endings**. He is shown with two faces because a threshold looks both ways:
what is ending, and what is beginning. **January** is named after him.

Markets are thresholds. Every decision stands between what was known and what
happens next. Janus is the instrument for that position.

The two faces are **not** duplicity. They are the two disciplines of the
product: **Memory** and **Foresight**. The name is an instrument, not an oracle.
It does not promise the future; it reasons about it in probabilities.

## Consequences

### Positive

- The name covers both halves of the loop without collapsing into “review tool”
  or “prediction tool”.
- The myth supplies a concrete image and a story that does not need a made-up
  compound.
- It is bilingual and brandable, and it leaves room for sub-brands: Memory,
  Foresight, BeliefBench.
- It does not encode “AI”, “stock”, or “open”, so the system can expand beyond
  equities without a rename.
- It does not promise returns, which is deliberate.

### Negative and risks

- **“Two-faced” means deceitful in English.** Mitigation: never use it in
  product copy; always pair the first mention with the subtitle.
- **Collisions:** Janus Henderson (asset manager), Janus Gateway (WebRTC),
  JanusGraph (graph database). Mitigation: consistent subtitle, repository
  topics, and a “Janus Market” descriptor if trademark pressure appears.
- **Mythological names can feel abstract.** Mitigation: concrete visual language,
  product copy that leads with the job, and a name section in the README.
- **SEO is crowded.** Mitigation: consistent topics and a distinct subtitle.

### Neutral

- The name does not encode the technology. That is intentional: the shell can
  change from DSH to another MCP client without renaming the product.
- The name does not encode the asset class. That is intentional: the loop is
  about beliefs and calibration, not only equities.

## Implementation

- README, CLI help, package descriptions, DSH plugin metadata, and GitHub
  description all use the same one-liner and subtitle.
- Repository topics: `market-agent`, `memory`, `forecasting`, `calibration`,
  `point-in-time`, `dsh`, `mcp`, `investment-research`.
- `docs/BRAND.md` is the source of truth for copy and visual direction.
- The wordmark is a gate line with two mirrored profiles, not a Roman bust.
